# VIXO 2.2.2 — server-backed App Review account

Source integration for bundle `sg.com.vixo.app` (Firebase Auth present in the uploaded IPA).

**Status:** Added to a temporary branch, NOT deployed to VIXO, not a modified/signed IPA. The repository has only a YarnPal research README; no VIXO application source or Firebase project access is present. No account credentials are stored here. This integration must be wired into the original VIXO app, its actual entitlement authorization path, and its authorized Firebase project before it can be tested end-to-end.

## Behavior

- A **single dedicated Firebase Auth account** can be provisioned for App Review. Its UID is enabled in a Firestore allowlist document and receives signed Firebase custom claims. Normal accounts keep their existing StoreKit and backend entitlement flow.
- The callable `vixoReviewAccess` checks the currently signed-in Firebase Auth user against the server-managed allowlist and disabled-account flag. It returns `{review: true, premium: true}` only for the dedicated account.
- The callable `vixoReviewLaunch` registers a new random `launchId` generated by the iOS process on every app launch. The service records that session as a fresh **app-managed device/session record**. It does **not** spoof hardware IDs, reset Firebase Installation IDs, evade trial/device limits, or alter Apple purchase records.
- Review credentials are used through VIXO's normal login screen, not hardcoded into a distributed app.

## Setup (authorized Firebase owner)

1. Use the Firebase project belonging to VIXO. Enable Email/Password sign-in and Cloud Firestore. Have `firebase-tools` installed for deploy.
2. For the provisioning script: `cd backend && npm install`; supply `GOOGLE_APPLICATION_CREDENTIALS` pointing to a **private** service-account JSON, `REVIEW_EMAIL` and `REVIEW_PASSWORD` (minimum 12 characters); then `npm run provision`. Never commit these values or the service-account file.
3. In this folder run `firebase deploy --only functions:vixoReviewAccess,functions:vixoReviewLaunch --project YOUR_VIXO_PROJECT` after setting the Firebase CLI project context. This syntax assumes the existing project has no conflicting function names/codebase; check existing deployment config first.
4. Add `ios/ReviewAccessService.swift` to your *original VIXO Xcode target*, adding FirebaseAuth and FirebaseFunctions if necessary. Call `initializeOnLaunch` after Firebase Auth restores the session. Call `signIn` via the existing login form. Only merge `reviewPremium == true` into premium UI/operations **after** the callable's verified response. The real backend must explicitly honor the demo entitlement for every premium operation that normally has server enforcement; this sample cannot modify VIXO's unknown backend.
5. Open the review account and verify all premium functions against the deployed backend. Keep the purchase UI functional; no forged receipts or locally forced entitlement flags.
6. In App Store Connect > App Review Information, give the reviewer the demo credentials and where to find the premium features. Apple also requests an **expired-subscription account** to review the full auto-renewable purchase flow (when applicable).
7. When finished, `cd backend && npm run revoke` with `REVIEW_EMAIL`. This disables the demo account and the server grant.

## What must still be integrated

The uploaded IPA is a compiled binary, not an editable Swift project. Its actual premium API, Firebase Auth project permissions, signing identity, and App Store Connect access were not provided. A GitHub branch cannot by itself create a real online account in the Firebase project or make the uploaded IPA use it. This is complete source for a standalone, opt-in review-auth adapter, **not** a claim that the VIXO production service now grants premium.

## Tests

`cd functions && npm test` tests the session ID validation. Test the deployed callables with real authorized and unauthorized Firebase accounts before shipping.
